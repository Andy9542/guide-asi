# Контракт спана решения контроля

Ставится не система наблюдаемости, а одно правило: **каждый контроль на каждое решение
эмитит спан** со стабильным набором полей. Имя спана — `defense.detect`.

| Поле | Тип | Смысл |
|---|---|---|
| `layer` | строка | Какой контроль принял решение — «политика на вызов», «скан зависимостей», «подпись шины» |
| `tool` | строка | Каким инструментом: `opa`, `semgrep`, `osv-scanner`, `ed25519` |
| `verdict` | `pass` \| `block` \| `flag` | Что решил |
| `step` | строка | На каком шаге агента |
| `latency_ms` | число | Во что обошлось решение |

Пример события:

```json
{
  "name": "defense.detect",
  "attributes": {
    "layer": "политика на вызов инструмента",
    "tool": "opa",
    "verdict": "block",
    "step": "write_config",
    "latency_ms": 4
  }
}
```

## Зачем именно так

Без этого контракта «нас не атаковали», «нас атаковали, и защита сработала» и «нас атаковали,
и защита молча пропустила» выглядят одинаково: тишина. Отсутствие инцидента — не доказательство
работающей защиты.

## Правило, выученное дорого

**Спан эмитит тот, кого проверяют.** Любой контейнер в зоне с доступом к коллектору может
отправить спан, включая скомпрометированного агента. Поэтому итоговый вердикт берётся
**из состояния системы** — строка в базе, файл на диске, отправленное письмо, — а телеметрия
отвечает на вопрос «что при этом видел контроль», а не на вопрос «что произошло».

Второе правило оттуда же: **отказ инструмента — это отдельный исход, а не «чисто»**. Если
сканер не запустился, вердикт не `pass`, а «вердикта нет».
