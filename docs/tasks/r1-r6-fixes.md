## Design

Цель — закрыть R1–R6 так, чтобы каждый контрпример стал регрессионной проверкой, по плану автора из комментария PR: четыре коммита в ветку `review-fixes`, без смены закреплённых версий, с одной новой зависимостью (PyYAML). Два места, где план уточнён по фактам разведки, названы явно.

**Semgrep (R1–R3).** Флаги обоих запусков собираются в одну переменную `SCAN_FLAGS` (вместо `IGNORE_OFF`) и получают `--disable-nosem`: указание из недоверенного кода не выключает детектор. Оба этапа Semgrep запускаются с `--json --verbose`, stdout и stderr разводятся по файлам во временном каталоге, а решение принимает хостовый помощник `scan_result.py` (stdlib): он строит ожидаемое множество файлов обходом каталога (профиль `.js .cjs .mjs .jsx .ts .tsx`, без `.git`, любой симлинк → «неполно»), сверяет его с `paths.scanned`, читает `errors[]` (Timeout, PartialParsing) и печатает одну строку вердикта; depscan.sh принимает решение по паре «код + строка» — код 1 python без строки «НАХОДКА» это ИНФРА, а не находка. Приоритет исходов остаётся `1 > 3 > 4 > 0`; при находке и неполноте — 1 с пометкой. Ветка стока для тела запроса ограничивается двумя формами объекта: `$REQ = $HTTP.request(...)` с regex на `$HTTP` и `$REQ = require('$MOD').request(...)` с regex на `$MOD` — уточнение плана: одной первой формы недостаточно (теряются два образца). Альтернатива «помощник внутри образа Semgrep» отклонена: тесты помощника всё равно идут на хосте, а инвентаризация через контейнер требует третьего монтирования; python3 на хосте и в CI уже обязателен для `build/selftest.sh`. Альтернатива «`--strict`» отклонена: пропуск по размеру даёт код 0.

**Red-team (R4).** До вызова модели `preflight.py` разбирает конфиг (`yaml.safe_load` + `yaml.compose` для сырого текста скаляров), принимает только поддержанный режим — один целевой провайдер, один промпт-строка, явный список `tests`, судья в `defaultTest.options.provider` разрешён — и отклоняет кодом 3 всё остальное, включая неоднозначные плоские скаляры YAML 1.1 («заключите в кавычки»). На выходе — байтовая копия конфига и манифест ожиданий: индексы `0..N-1`, нормализованные `vars`+`assert` каждого теста (defaults слиты как у promptfoo), провайдер и промпт; ключей доступа в манифесте нет. `run.sh`: preflight → promptfoo на копии с выгрузкой на свежий уникальный путь → публикация в `REDTEAM_JSON` (ошибка записи → 3) → `classify.py … --expected manifest.json`. Классификатор без манифеста не работает; с ним сверяет число строк, множество `testIdx`, единственный `promptIdx`, провайдера, `testCase` каждой строки и единственную запись `results.prompts`. PyYAML закрепляется в `requirements.txt` и ставится в CI тем же способом, что cryptography.

**Подпись (R5–R6).** `verify()` требует именованный `guard` (пропуск — `TypeError` Python, `None` — `TypeError` с текстом); проверка только подписи и адресата выделяется в `verify_signature()` с явным контрактом «повтор не отсекает». В `ReplayGuard` очистка, проверка nonce и лимита, регистрация — одна критическая секция под `threading.Lock`; криптопроверка по-прежнему до `accept`. Демо держит один долгоживущий `GUARD` на получателя, положительные проверки берут свежие конверты. Новый `signing_test.py` (unittest) проверяет последовательный повтор, обязательность guard, конкурентное предъявление одного конверта и конкурентное заполнение — с расширением окна гонки через подмену `_seen` (уточнение плана: барьер на старте без расширения гонку не ловит), с таймаутами барьера и join.

**Согласование (коммит 4).** README трёх каталогов и `configs/README.md` по факту, `docs/tasks` — «изменение → тест → результат на SHA», заголовок и описание PR. Границы, которые остаются и называются в README: тайм-аут правила 5 с на файл даёт 3, а не 0; симлинки в каталоге → 3; профиль расширений фиксирован; red-team поддерживает один провайдер и один промпт; guard — один на получателя внутри процесса, распределённое хранилище не входит.

Совместимость (одобрено планом автора): `verify(…, guard=…)` обязателен, старые вызовы падают `TypeError`; `classify.py` требует `--expected`; `depscan.sh` требует `python3`; `run.sh` запускает promptfoo на копии конфига. Потребителей вне репозитория нет, README каталогов перечисляют изменения.

### Principles

- PC1 — Помощники печатают ровно одну строку вердикта в stdout (`scan_result: …`, `REDTEAM_VERDICT=…`), диагностику — в stderr; вызывающий скрипт решает по паре «код + строка», а не по одному коду.
- PC2 — Симлинки в проверяемом каталоге дают 3 без попытки их разрешить: это заявленная граница учебного профиля.
- PC3 — Правятся только `configs/{semgrep,redteam,bus-signing}`, `configs/README.md`, `build/selftest.sh`, `.github/workflows/selftest.yml`, `docs/tasks/r1-r6-fixes.md`; тексты гайда и `docs/tasks/review-fixes.md` не трогаются.
- PC4 — Тесты гонки утверждают число принятых конвертов и согласованность структур, не номера строк и не наличие `Lock` в исходнике; барьеры и join — с таймаутом.
- PC5 — POSIX sh; большой файл для selftest генерируется во временном каталоге внутри дерева репозитория (`$HERE/.selftest-big.XXXXXX` + trap), потому что snap-docker монтирует `/tmp` пустым; мегабайты наполнителя не коммитятся.

### Assumptions

- AS1 — Раннер CI ставит `pyyaml` с PyPI тем же шагом, что cryptography.
- AS2 — Форматы, снятые разведкой, стабильны для закреплённых версий: JSON Semgrep 1.176.1 (`paths.scanned`, `paths.skipped` с `--verbose`, `errors[].type` строка или массив) и экспорт promptfoo 0.123.0 (`testIdx`, `promptIdx`, `provider`, `testCase`, `results.prompts`).
