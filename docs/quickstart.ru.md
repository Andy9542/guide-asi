# Быстрый старт

[Обзор](../README.ru.md) · [English](quickstart.md)

Начните с небольшой локальной проверки, затем выберите контроль для своей архитектуры.
Команды рассчитаны на POSIX shell в Linux, macOS или WSL и Python 3.10+.

## 1. Проверить контракт оценки

```sh
git clone https://github.com/Andy9542/guide-asi.git
cd guide-asi
python3 configs/redteam/classify_test.py
```

Если репозиторий уже скачан, выполните только последнюю команду из его корня.
Ожидаем `classify_test: 58 случаев, расхождений 0`, код 0.

После клонирования нужны только Python и стандартная библиотека. Локальные фикстуры
формата promptfoo проверяют отсутствующие результаты, кэшированные ответы и ошибки
оценщика. Сеть, модель, API-ключ, Docker и Node.js этому шагу не нужны.
Стойкость живого агента здесь не измеряется.

## 2. Проверить допуск конфигов

Из корня репозитория создайте отдельное Python-окружение:

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r configs/redteam/requirements.txt
python3 configs/redteam/preflight_test.py
```

Для установки зависимости нужен доступ к реестру пакетов; сами проверки локальные.
Ожидаем `preflight_test: 85 случаев, расхождений 0`, код 0.
Если в Debian/Ubuntu создание окружения сообщает об отсутствии `ensurepip`, установите
пакет дистрибутива `python3-venv`.

Preflight ограничивает профиль конфига до вызова promptfoo, в том числе отклоняет
динамическое значение assertion с `package:`. Содержимое `provider.config` остаётся
доверенным входом: валидатор не изолирует исполнение враждебных конфигов.

## 3. Запустить локальный echo-прогон

Оставьте виртуальное окружение активным. Нужен Node.js с npm/npx; CI использует Node 22.
Первый запуск скачивает **promptfoo 0.123.0 с зависимостями**: в репозитории зафиксирован
размер npm-установки около **2,6 ГБ**. Предусмотрите место и время на загрузку.
Сам провайдер echo не использует модель или API-ключ.

```sh
(
  work=$(mktemp -d) || exit 3
  trap 'rm -rf "$work"' EXIT
  trap 'exit 130' INT
  trap 'exit 143' TERM
  export PROMPTFOO_DISABLE_TELEMETRY=1 PROMPTFOO_DISABLE_UPDATE=1
  export PROMPTFOO_CONFIG_DIR="$work/promptfoo"
  export REDTEAM_CONFIG="$PWD/configs/redteam/testdata/echo-pass.yaml"
  export REDTEAM_JSON="$work/results.json"
  sh configs/redteam/run.sh
)
```

Ожидаем `REDTEAM_VERDICT=pass`, код 0. Замените `echo-pass.yaml` на `echo-fail.yaml`,
чтобы проверить отрицательный результат: `REDTEAM_VERDICT=fail`, код 1.
Временная выгрузка удаляется при выходе из подоболочки; npm-кэш сохраняется.

Контракт red-team-обвязки: **0 — прошло, 1 — провалено, 3 — инфраструктурная ошибка,
вердикта нет**. Echo проверяет работу обвязки. Для оценки модели прочитайте
[инструкцию red-team](../configs/redteam/README.md), проверьте профиль конфига и
подключите шлюз. Вызовы живой модели могут тарифицироваться провайдером.

## 4. Выбрать контроль

| Вопрос | С чего начать | Что проверить |
|---|---|---|
| Может ли агент переписать свой MCP-конфиг? | [OPA](../configs/opa/) | Запрет защищённого пути, разрешение обычного, отдельный исход сломанной политики |
| Что устанавливается с зависимостями агента? | [Semgrep + OSV](../configs/semgrep/) | Различаются находки, чистый результат и неполный скан |
| Кто прислал сообщение и не принимали ли мы его раньше? | [Подпись сообщений](../configs/bus-signing/) | Отправитель, адресат, подмена, свежесть и повторы |
| Видно ли решение контроля? | [OpenTelemetry](../configs/otel/) | Поля спана решения и работа развёрнутого коллектора |
| Где должны находиться ключи модели? | [LiteLLM](../configs/litellm/) | Граница шлюза, ключи, доступ и живая интеграция |

В каждом примере описаны замеры и ограничения. Для ревью архитектуры пройдите по
[семи точкам внедрения](../README.ru.md#точки-внедрения).

## Полная самопроверка

Нужны Docker с работающим daemon, Node.js/npm/npx, OpenSSL и Python с PyYAML и cryptography.
PyYAML устанавливается выше; версию cryptography возьмите из selftest подписи, как это
делает CI. Команды выполняются из корня репозитория:

```sh
pin=$(sed -n "s/^CRYPTOGRAPHY_VERSION='\(.*\)'$/\1/p" configs/bus-signing/selftest.sh)
test -n "$pin" && python3 -m pip install "cryptography==$pin"
sh build/selftest.sh
```

Самопроверка при необходимости скачивает закреплённые пакеты и образы, затем проверяет
локальные сервисы. Эталон окружения — [workflow](../.github/workflows/selftest.yml):
Ubuntu 24.04, Python 3.12, Node 22. Проверки живого шлюза и коллектора описаны отдельно
в каталогах их конфигов.
